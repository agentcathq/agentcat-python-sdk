# AgentCat Python SDK v2 Audit — MCP 2026-07-28 Compatibility

> **Superseded in part (2026-08-03).** Everything below calls the handle
> `task_id`. It is now **`session_id`** throughout — the old name collided with
> the MCP Task extension (`tasks/*`), and AgentCat's handle is not an MCP task.
> The rename is mechanical (`TASK_ID_PARAM` → `SESSION_ID_PARAM`,
> `agentcat_task_id_source` → `agentcat_session_id_source`, `resolve_task_id` →
> `resolve_session_id`, `derive_task_id` → `derive_session_id`, and so on), and
> the four frozen derivation vectors are unchanged. One behavior change came
> with it: AgentCat now honors only handles it issued — see
> `agentcat-typescript-sdk/docs/superpowers/specs/2026-08-02-session-id-validation-design.md`
> and `tests/test_session_id_validation.py`. Read this document for the
> architecture; read the code for the names.

**Date:** 2026-08-01
**Inputs:** `2026-07-28-cross-sdk-changelog.md` (behavioral spec, Appendices A/B are
byte-authoritative), AgentCat TypeScript SDK `2.0.0-beta.4`
(`feat/explicit-handles-v2`, north star), local reference checkouts:
`reference-sdks/mcp-python-sdk` @ v2.0.0, `reference-sdks/mcp-python-sdk-v1` @
v1.29.0, `reference-sdks/fastmcp` @ v4.0.0b1, `reference-sdks/fastmcp-v3` @ v3.4.5.
**Scope:** what must change in `agentcat` (Python, currently 1.0.2) to ship v2.0.0:
explicit `task_id`/`agent_id` handles, stateless per-request resolution, and
dual-generation support for the official MCP SDK (1.x **and** 2.x) plus community
FastMCP 3.x **and** 4.0.

Line references are to the repos above as of this date.

## 1. Landscape summary

### 1.1 Protocol 2026-07-28 (what we must absorb)

Per the cross-SDK changelog: no initialize handshake, no `Mcp-Session-Id`,
per-request self-describing metadata under `io.modelcontextprotocol/*` keys,
MRTR (a tool call may return `resultType: "input_required"` and complete on a
continuation round carrying `inputResponses`). AgentCat replaces all session
machinery with explicit stateless handles: `task_id` (echoed tool parameter,
`ses_` KSUID stored in `Event.sessionId` — zero backend changes) and opt-in
self-chosen `agent_id` (event tags). Canonical agent-facing copy and tag names
are fixed in changelog Appendix A/B and TS `src/modules/constants.ts` — reuse
byte-identical.

### 1.2 Official MCP Python SDK v2.0.0 — server-side changes that hit us

The low-level server was **rebuilt, not renamed** (`docs/whats-new.md:48`).

| Seam we use today (v1.29) | v2.0.0 replacement |
| --- | --- |
| `Server.request_handlers: dict[type, handler]` (public, `lowlevel/server.py:156`) | `Server._request_handlers: dict[str, HandlerEntry]` keyed by method string, `HandlerEntry(params_type, handler)` is **frozen** (`lowlevel/server.py:92,427`); public `add_request_handler(method, params_type, handler)` / `get_request_handler(method)` (`:472,514`) |
| Handler signature `async (req: CallToolRequest) -> ServerResult` | `async (ctx: ServerRequestContext, params: CallToolRequestParams) -> CallToolResult \| InputRequiredResult` |
| `server.request_context` contextvar (`lowlevel/server.py:109,239`) | **Removed** — context is the first handler argument (`docs/migration.md:1625`) |
| `mcp.server.fastmcp.FastMCP` with `_mcp_server` + `_tool_manager` | **Module gone.** New `mcp.server.mcpserver.MCPServer` with `_lowlevel_server` + `_tool_manager` (survives) (`mcpserver/server.py:190,199`; `docs/migration.md:873`) |
| Client identity from initialize: `request_context.session.client_params.clientInfo` | Ladder: `ctx.meta["io.modelcontextprotocol/clientInfo"]` (constants `CLIENT_INFO_META_KEY`, `mcp_types/_types.py:53-63`), `ctx.protocol_version`, synthesized `ctx.session.client_params.client_info` (snake_case, may be `None`) |
| camelCase model fields (`inputSchema`, `isError`, `structuredContent`), `extra="allow"` | **snake_case** (`input_schema`, `is_error`, `structured_content: Any`); unknown extras **silently dropped** — custom data must ride `_meta` (`docs/migration.md:328-358`) |
| Tool results: bare content lists wrapped by SDK | Handlers must return full `ListToolsResult`/`CallToolResult`; bare lists are TypeErrors (`docs/whats-new.md:102`) |

MRTR types: `InputRequiredResult` (`result_type == "input_required"`,
`mcp_types/_types.py:2074`), continuation params
`CallToolRequestParams.input_responses` / `.request_state` (`:871,1449`).

Other v2 facts that shape the design:

- `initialize` **cannot** be overridden via `add_request_handler` (raises,
  `lowlevel/server.py:490`); it is legacy-path-only anyway.
- Provisional `Server.middleware` list exists (`docs/migration.md:1577`) but is
  marked provisional/TODO — not a stable seam.
- No per-request `Server` factory in this SDK: `StreamableHTTPSessionManager`
  holds one `Server`; the 2026 path builds a per-request `Connection`
  (`streamable_http_manager.py:79`, `runner.py:781`). Rebuild-on-demand still
  matters for replicas behind an LB and late `track()`.
- `stateless_http` still exists but only affects 2025-era clients
  (`docs/whats-new.md:159`).
- `requires-python >= 3.10` — no floor bump needed. `mcp-types` requires
  `pydantic>=2.12.0`.

### 1.3 Community FastMCP 4.0.0b1 — changes vs 3.4.5

v4 = **v3 middleware surface + mcp SDK v2 engine + sessionless protocol**
(changelog `docs/changelog.mdx` v4.0.0b1; `docs/getting-started/whats-new.mdx`).

Stable across v3→v4 (our integration surface survives):

- `fastmcp.server.server.FastMCP`, `_local_provider`, `add_middleware`,
  `middleware`, `server.add_tool(...)` (v4 `server.py:344,478,591,1800`).
- Middleware hooks and `MiddlewareContext` fields unchanged: `on_call_tool`,
  `on_list_tools`, `message`, `fastmcp_context`, `method`, `.copy()`
  (v4 `middleware/middleware.py:93-279`).
- Internal `Tool.parameters` (input schema) / `Tool.output_schema`;
  `tool.model_copy(update=...)` is the sanctioned rewrite pattern (their own
  `DereferenceRefsMiddleware` does it, `dereference.py:44`).
- Wraps official lowlevel Server as `self._mcp_server` in **both** (v4
  `server.py:429`, v3 `:412`).

Breaking/behavioral for us:

- **Detection:** our v3 probe set (`_local_provider` + `add_middleware` +
  `middleware`, no `_tool_manager`) matches v4 too → v4 misclassified as v3.
  v4 discriminators: `add_extension` / `_extensions` (`server.py:484,594`),
  `_request_state_security` (`:402`), `fastmcp.__version__` major.
- v4 imports `mcp_types` (snake_case). camelCase reads (`params.clientInfo`,
  `structuredContent`) only work through a deprecation bridge scheduled for
  removal.
- `Middleware.on_initialize` **never fires** on modern (2026) connections
  (`docs/getting-started/upgrading/from-fastmcp-3.mdx:430`) — initialize-based
  capture is dead there.
- Arg-strip must preserve MRTR fields: our v3 strip rebuilds
  `CallToolRequestParams(name=..., arguments=...)` and would **drop**
  `input_responses` / `request_state` / `_meta` on v4
  (ours: `overrides/community_v3/middleware.py:228-232`; theirs:
  `server.py:1407-1420`).
- Results may be `InputRequiredToolResult` — don't treat as payload
  (`tools/base.py:187-222`).
- `ResponseCachingMiddleware` caches list/call results — AgentCat middleware
  must sit **outermost** so injected schemas/mint-backs aren't cached-around.
- `fastmcp.tools.tool` import path removed (our TYPE_CHECKING import breaks).
- Deps: `mcp>=2.0.0,<3`, `mcp-types>=2.0.0,<3`, `pydantic>=2.12.0`,
  `requires-python >= 3.10`.
- FastMCP 2.x remains on mcp 1.x with the old `_tool_manager` architecture —
  unchanged from what we support today.

### 1.4 TypeScript SDK v2 (north star)

Public surface (`src/types.ts:1-44`, `src/index.ts:213-217,363-367`):

- `track(server, projectId, options)` — never throws; failure logs + returns
  untracked server.
- Options added: `enableAgentTracking` (default false), `resolveTaskId`
  (hook mode). Removed/changed: identify runs per call (no cache); no session
  options.
- `publishCustomEvent(serverOrSessionId, projectId, eventData)` with
  `CustomEventData.taskId` (verbatim, never derived; takes precedence).
- `AgentCatIDPrefixes` now includes `Agent = "agt"` (reserved).

Mechanics (all specified in changelog §3–§6; implemented in TS
`src/modules/handles.ts`, `src/engine/*`):

- Mint `ses_` KSUID per call when no `task_id` supplied; supplied values
  trusted verbatim (trim-only check). `task_source ∈ supplied|minted|hook`.
- Deterministic hook derivation (changelog §3.6): SHA-256 of
  `customer_id[:project_id]`, timestamp = 2024-01-01 epoch + `uint32_be(hash[0:4]) % 31536000000`
  ms, payload = `hash[4:20]`, standard KSUID base62 → `ses_` + 27 chars.
  **Golden vectors** (TS `src/tests/handles.test.ts:53-68`):
  - `("customer-abc", "proj_1")` → `ses_2cOHEO0LYGADMzRvWTXXVbbgxgm`
  - `("customer-abc", None)` → `ses_2cZY3tvyI25O2AmL2CGVo2B1IIj`
  - `(" x ", "p")` → `ses_2c3yR5mYKQdLaXsJNgZH6erbfQK`
  - `("x", "p")` → `ses_2bw285VY9apdgUgTPXKFnT6P4G0`
- Injection pipeline (pure): order customer params → `task_id` → `agent_id` →
  `context`; deep copy; drop `additionalProperties: false`; skip composed
  schemas; collision-skip + warn; registries (injected-params + output-injection)
  drive stripping and mirroring; rebuild-on-demand from the original list
  handler when a call lands with no registry; heuristic strip fallback
  (`task_id`/`agent_id`/`context`, except `get_more_tools` keeps `context`).
- Mint-back: text block only on mint (never hook mode), also on `isError`
  results; `_mcp_instructions` mirror on every response into plain-object
  `structuredContent` gated by output registry; customer key wins; event
  records the **undecorated** result.
- `agent_id`: required-in-schema, soft server-side; tags
  `agentcat_agent_id` (CR/LF→space, ≤200 chars) + `agentcat_agent_id_source`.
- Client identity ladder per request: envelope → `_meta` → legacy initialize
  capture. Protocol version → `agentcat_protocol_version` tag.
- MRTR tags `agentcat_mrtr = input_required|continuation`; intermediate rounds
  are never decorated.
- Copy constants to reuse byte-identical (TS `src/modules/constants.ts:20-62`):
  `TASK_ID_PARAM_DESCRIPTION`, `AGENT_ID_PARAM_DESCRIPTION`,
  `AGENT_ID_PARAM_DESCRIPTION_HOOK_MODE`, `MINT_BACK_HEADER_TASK`,
  `MINT_BACK_CLOSER`, `mintBackTaskLine`, `mintBackConfirmed`,
  `MCP_INSTRUCTIONS_FIELD_DESCRIPTION`, `MCP_INSTRUCTIONS_TASK_ID_DESCRIPTION`,
  `MCP_INSTRUCTIONS_AGENT_ID_DESCRIPTION`, `MCP_INSTRUCTIONS_KEY`,
  `META_CLIENT_INFO_KEY`, `META_PROTOCOL_VERSION_KEY`, and the five
  `agentcat_*` tag names.

## 2. Current Python SDK — inventory

### 2.1 Reusable as-is or with small changes

- Event queue + processing order (redact → sanitize → truncate → send):
  `modules/event_queue.py:106-154,289-326`.
- Exporters (`modules/exporters/*`), diagnostics (`modules/diagnostics.py`),
  logging, truncation/sanitization/redaction, exceptions capture.
- Per-server storage via `weakref.WeakKeyDictionary`
  (`modules/internal.py:14-16`) — already matches changelog §6.3 guidance.
- Vendored KSUID (`thirdparty/ksuid/ksuid.py`) — has `from_bytes` +
  base62 `__str__` (zfill 27); deterministic derivation is implementable as
  `bytes(uint32_be((ts_ms - 1400000000000)//1000)) + hash[4:20]` → base62.
- `get_more_tools` handler + schema (`modules/tools.py:13-44`) — description
  already byte-identical to TS; needs `readOnlyHint` annotation + handle
  injection (not exempt) + context preserved on strip.
- Tag/property callback resolution (`modules/internal.py:123-192`) and tag
  validation — needs an SDK-owned-tags merge that bypasses customer validation
  and the 50-tag cap.
- Event tags/properties, `identify` (already cache-less per call:
  `modules/identify.py:9-42`) — but the separate `agentcat:identify` event goes
  away; result gets stamped on the tool-call event instead.

### 2.2 To be removed (changelog §3.1)

- `modules/session.py` session machinery: `new_session_id` rollover,
  `INACTIVITY_TIMEOUT_IN_MINUTES` (30), `get_server_session_id`
  (`session.py:183-200`), `last_activity` bookkeeping, stateless client-info
  header fallbacks used for session identity.
- `AgentCatOptions.stateless` + `_detect_stateless` (`__init__.py:35-54`) —
  meaningless once sessions are gone.
- `AgentCatData.session_id/session_info/last_activity/is_stateless` and the
  identity fields on `SessionInfo` (client name/version become per-request).
- Event emissions for `mcp:initialize`, `mcp:tools/list`, and
  `agentcat:identify` (interception of initialize/tools-list remains where it
  exists, for capture/injection — they just publish nothing).
- Transport-session reads for correlation (`request_extra.py:158-181` reads
  `mcp-session-id` into `parameters.extra.sessionId` — see Open decision 5).

### 2.3 Not present today (net-new)

- Handle primitives module: mint, extract, deterministic derive (+ golden
  vectors), mint-back text builder, `_mcp_instructions` mirror builder, agent
  tag clamp.
- Injected-params + output-injection registries; pure injection pipeline
  (today's context injection is inline per flavor and never touches
  `additionalProperties` or composed schemas: `context_parameters.py:26-56`).
- Output-schema extension (`_mcp_instructions` optional property) — nothing
  touches `outputSchema` today.
- Per-request client identity ladder + protocol version tag; envelope/`_meta`
  reads (`rg io.modelcontextprotocol src/` → zero hits today).
- MRTR detection/tagging.
- `agent_id` support end-to-end.
- Official SDK v2 adapter (method-string handlers, ctx-as-argument) and
  `MCPServer` support; FastMCP v4 discriminator + snake_case/MRTR-safe
  middleware.
- `publish_custom_event` (Python has no custom-event API at all today; TS does
  — see Open decision 2).

## 3. Gap analysis — required changes by area

### 3.1 Handle primitives (new `modules/handles.py`)

- `new_task_id()` → `ses_` KSUID (reuse `generate_prefixed_ksuid`).
- `derive_task_id(id, project_id)` — changelog §3.6 algorithm; pin the four TS
  golden vectors in tests (cross-language contract). Caller trims; derive does
  not.
- `extract_handle(args, name)` — trimmed non-empty `str` else absent; verbatim
  trust.
- `resolve_handles(...)` — prompted vs hook mode; `task_source`
  supplied/minted/hook; hook errors/None → silent random mint (log, never
  agent-facing); agent extraction only when `enable_agent_tracking`.
- Mint-back builders: text block (exact 3-line format), confirmed copy
  (`task_id and agent_id` + pluralization), `_mcp_instructions` object
  (omission rules: no `task_id` key in hook mode; no `agent_id` key unless
  supplied; nothing if neither).
- Tag builder: `agentcat_task_id_source` always; `agentcat_agent_id`
  (CR/LF→space, ≤200), `agentcat_agent_id_source`, `agentcat_protocol_version`,
  `agentcat_mrtr` conditionally. SDK tags merge **after** customer tags,
  exempt from the 50-tag cap and customer validation.

### 3.2 Options & public API (`types.py`, `__init__.py`)

- Add `enable_agent_tracking: bool = False` and
  `resolve_task_id: Callable[[Any, Any], str | None | Awaitable[str | None]] | None = None`
  (docstrings adapted from TS JSDoc; prefer the types.ts wording — the
  index.ts `@param` line for agent tracking is stale on "minted by server").
- Remove `stateless`. Keep everything else (`identify`, redaction, exporters,
  tags/properties, `custom_context_description`, ...).
- `AgentCatData` slims to `project_id`, `options`, plus per-server engine
  state: injected-params registry (`dict[str, set[str]]`), output-injection
  registry (`set[str]`), original-list-handler ref for rebuild.
- `track()` **never throws** (changelog §6.3): today `ValueError`/`TypeError`
  propagate (`__init__.py:198-202`) — v2 logs + returns the server untracked.
  Module-level state stays first-wins.
- Version bump to `2.0.0` (see Open decision 6 re: beta), `EventType` prunes to
  tool-call (+ custom); constants file gains the Appendix A/B strings.

### 3.3 Shared injection pipeline (new `modules/injection.py`)

Pure function: `(options, listed_tools) -> (advertised_tools, injected_params_registry, output_registry)`.

- Param order customer → `task_id` → `agent_id` → `context`; deep-copy schemas
  (per-SDK-flavor copy strategy: `model_copy(deep=True)` for pydantic tools,
  `copy.deepcopy` for dict schemas); remove `additionalProperties: false`;
  skip composed schemas with warning; collision-skip per param with warning
  (customer's own `task_id` must reach their handler — never stripped).
- `task_id` optional; `agent_id` **added to `required`**; hook mode injects no
  `task_id` and uses `AGENT_ID_PARAM_DESCRIPTION_HOOK_MODE`.
- `get_more_tools` included (handles injected; its `context` is bespoke).
- Output side: for every tool with plain-object `output_schema`, add optional
  `_mcp_instructions` property (sub-descriptions from Appendix A); record in
  output registry; composed → warn, content-only mint-back.
- Determinism is a hard requirement (rebuild-on-demand equality).

### 3.4 Call path (per flavor, shared helpers)

resolve handles → identify → client-info ladder → strip (cloned) → dispatch →
MRTR probe → mint-back/mirror (wire only) → publish event (raw request,
undecorated response, `Event.sessionId = task_id`, actor + client fields, SDK
tags). Error results also get mint-back. Fallback heuristic strip when no
registry and rebuild failed.

### 3.5 Per-flavor adapters

| Flavor | Detection (per-object) | Seam | Notes |
| --- | --- | --- | --- |

| lowlevel v2 | has `_request_handlers` (str-keyed) + `add_request_handler`; no `request_context` | replace `_request_handlers["tools/call"|"tools/list"]` with new frozen `HandlerEntry(params_type, wrapped)` | ctx arg carries `meta`/`protocol_version`/`session`; snake_case; must return full result models; MRTR union |

### 3.6 Per-request client identity / actor identity

- Ladder (changelog §5.1): envelope → `_meta` → legacy initialize capture.
  Python mapping: lowlevel v2 `ctx.meta[CLIENT_INFO_META_KEY]` (TypedDict);
  lowlevel v1 `request.params.meta` extras (`RequestParams.Meta` is
  `extra="allow"`); legacy = v1 `request_context.session.client_params.clientInfo`
  / v2 `ctx.session.client_params.client_info`; FastMCP v3/v4
  `fastmcp_context.request_context.meta` + initialize capture only on
  handshake era. Narrow: accept `name`/`version` only if individually `str`.
- Protocol version: same ladder; v2 also `ctx.protocol_version`. Tag
  `agentcat_protocol_version`.
- Identify: stamp result onto the tool-call event
  (`identify_actor_given_id/name`, `identify_data`); delete the
  `agentcat:identify` event type; SessionInfo-as-cache disappears —
  server name/version + SDK metadata stamped at publish from server object +
  package metadata.

### 3.7 Event pipeline changes

- `Event.session_id` carries the task ID (`ses_` prefix preserved; wire field
  unchanged — zero backend migration).
- Publish only `mcp:tools/call` (+ `agentcat:custom` if custom events land).
- Raw request recorded unstripped; response recorded undecorated.
- SDK tags merged post-customer-tags, exempt from cap/validation.
- `duration`/timestamps, redaction/sanitization/truncation unchanged.

### 3.8 Packaging, CI, docs

- `pyproject.toml`: version `2.0.0`; `mcp>=1.2.0,<3`; **relax

- Dev/test env: uv **conflict groups** `mcp-legacy` (mcp 1.x) / `mcp-modern`

- CI: `mcp-compatibility.yml` discovery keeps testing every mcp minor ≥1.2

## 5. Risks & gotchas

1. **pydantic resolver wall:** `agentcat[community]` with fastmcp 4 forces
   pydantic ≥2.12 at install time; our `<2.12` pin makes v2 uninstallable
   alongside it. Relaxing risks customers on old pydantic — the original pin
   (#16) reason should be re-verified against `agentcat-api==1.0.0` models.
2. **Frozen `HandlerEntry`:** wrapping must replace the entry, not mutate it;
   re-registration after `track()` (customer calls `add_request_handler`
   later) needs a re-arm story (TS solves via `registrationPatch`).
3. **v2 outbound validation:** `_serialize` validates results per protocol
   version — malformed injected schemas / mirrors raise server-side. Injection
   must produce schema-valid output on both eras (snake_case vs camelCase
   serialization).
4. **Extras dropped in v2 models:** never attach unknown attributes to v2
   pydantic objects; `structured_content` is `Any` (safe), `Tool` extras are
   not (use real fields only).
5. **FastMCP 4 strip bug class:** rebuilding params without MRTR fields
   severs continuations — must `model_copy(update={"arguments": ...})`.
6. **Middleware ordering (v4):** response caching / dereference middlewares
   can cache or rewrite around us; AgentCat must be outermost and re-inject on
   whatever list result it sees.
7. **In-place mutation on the v1 path today** (`arguments.pop("context")`,
   shared dict) violates the copy rule and can corrupt concurrent retries —
   v2 rewrite fixes it, but the v1 adapter must be audited for every mutation.
8. **`get_more_tools` context:** heuristic fallback strip must except it, or
   its real parameter is destroyed (changelog §6.2).
9. **Float precision in derivation:** compute the KSUID timestamp in integer
   milliseconds (`(ts_ms - 1400000000000) // 1000`), never through
   `datetime.timestamp()` floats, or golden vectors will drift on boundaries.
10. **camelCase bridge removal (fastmcp 4.x):** code must be snake_case-first
    with camelCase fallback for v3, not the reverse.
11. **Diagnostics/event-queue globals:** first-wins init already holds, but
    `track()`-in-factory patterns mean repeated `track()` calls must stay
    idempotent per server object (weak-keyed state covers this).

1. **Community FastMCP 2.x support:** drop in agentcat v2 (recommended — the
   local uv.lock experiment already excludes it; fastmcp 2.x predates the

   keep 7-flavor support.

   semantics: verbatim task ID, `CustomEventData.task_id` precedence,
   `agentcat:custom` type) or defer to 2.1.

   (recommended: deterministic, mirrors TS engine, private-API-friendly per
   our CI change detection) vs build on the provisional `Server.middleware`.
4. **Official FastMCP v1 path consolidation:** keep today's ToolManager
   monkey-patching, or re-route official-FastMCP-v1 through the lowlevel-v1
   engine on `_mcp_server` (one engine, fewer patch surfaces — recommended).
5. **`parameters.extra.sessionId` telemetry:** changelog says transport
   session IDs are ignored for correlation; keep capturing `mcp-session-id`
   into the raw-request `extra` (telemetry-only, recommended) or remove
   entirely.
6. **Release train:** ship `2.0.0b1` prerelease first (matches TS
   `2.0.0-beta.4` posture + fastmcp 4.0.0b1 timing) or straight to `2.0.0`.
